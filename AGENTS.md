# Private configuration boundary

- Never read, open, print, copy, hash, parse, load, upload, or otherwise access `.env` or private `.env.*` files. Do not inspect their contents through shell tools, Python, dotenv, Git, scanners, hooks, a child process, or another agent.
- A static `.env.example` template may be edited without consulting any private file.
- Never run `quant-binance` / `python -m quant_binance` from this project as an agent: its normal configuration loader opens `.env`. Account authentication must be performed by the user in their own terminal.
- For network diagnostics use `scripts/probe_binance_network.py`, which makes unauthenticated public requests and never loads project configuration, environment credentials, or dotenv files.
- Secret scans and Git hooks must inspect only Git index contents; do not load local secrets to compare against tracked files.
- Do not change, stop, restart, or reconfigure the user's proxy/VPN/TUN software, system proxy, DNS, firewall, or routing table. Only per-request proxy settings and per-socket interface binding are allowed for diagnostics.
- Do not claim that a file-deny policy is enforced by an already-running full-access session. Verify configuration without attempting to read protected files.
- Per the user's 2026-09-14 request, all clients use ordinary sockets with `trust_env=False` and normal HTTPS certificate verification, following the OS route and any user-enabled TUN. Do not add explicit proxies or modify proxy/VPN/TUN software or system network settings. Public diagnostics use `scripts/probe_binance_network.py`. This does not change Codex's own proxy setup.
- Select the network in code or the CLI. Mainnet uses `BINANCE_API_KEY_MAIN` / `BINANCE_API_SECRET_MAIN`; testnet uses `BINANCE_API_KEY_TEST` / `BINANCE_API_SECRET_TEST`. Never fall back between key pairs or use a dotenv network variable to select an account.
- `scripts/verify_accounts.py` and `quant_binance.verification.verify_account` load local credentials; users must run them in their own terminal. Agents must not execute these against real configuration. Offline tests must use in-memory fake configuration and must never access a private dotenv file.
- `scripts/testnet_workbench.py` may collect public testnet market data and simulate fills; it never loads dotenv or account credentials. Exchange orders are separate from these simulations.
- Never run `python -m quant_binance.testnet_execution` as an agent: it loads private configuration. The user must start account verification and testnet order execution in their own terminal.
- `scripts/strategy_lab.py` and `quant_binance.lab` may read the public `strategy.toml`, collect unauthenticated public market data and persist virtual trades. They never load dotenv or credentials and have no exchange-order path. The lab's 50 USDT simulations must not be presented as actual testnet trades or evidence authorizing mainnet trading.
- `scripts/tactical_lab.py` uses only public `tactical.toml`, public market evidence and local virtual ledgers. Its `review` command records a one-use expiring paper decision; it must not be described as an authenticated exchange order or delegated mainnet trading authority. The user requested only the current review, not recurring Codex reviews. Never run the account configuration loader to support this public workflow.
